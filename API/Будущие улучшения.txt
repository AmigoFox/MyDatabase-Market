📌 Roadmap развития API
1. Pagination (пагинация)

Добавить постраничную загрузку заказов.

Пример:

GET /api/v1/orders?page=1&pageSize=10

Что даст:

API не будет возвращать тысячи записей

быстрее ответы

меньше нагрузка на БД

удобнее для клиента (MAUI / сайт)

2. Projection (оптимизация EF Core)

Сразу формировать DTO в запросе EF Core.

Сейчас:

DB → Entity → DTO → JSON

Будет:

DB → DTO → JSON

Плюсы:

меньше памяти

быстрее запросы

меньше работы EF Core

3. Удаление лишних Include

Сейчас используется:

.Include()
.ThenInclude()

Иногда это грузит слишком много данных.

Лучше:

.Select(new DTO {...})

Это уменьшает SQL и ускоряет API.

4. Pagination + Infinite Scroll (для MAUI)

Добавить подгрузку заказов по мере прокрутки.

Пример:

GET /orders?page=2

MAUI будет догружать заказы.

5. Кэширование курсов валют

Сейчас курсы валют берутся из БД.

Можно добавить:

MemoryCache
или
Redis

Это уменьшит нагрузку на БД.

6. Rate Limiting

Ограничить количество запросов.

Например:

100 запросов / минута

Это защитит API от:

спама

DDOS

ботов

7. Logging (логирование)

Добавить логирование:

Serilog
Seq
Elastic

Логи:

ошибки
запросы
платежи
авторизация
8. Validation (проверка входных данных)

Добавить строгую проверку DTO.

Например:

FluentValidation

Плюсы:

защита API

понятные ошибки клиенту

9. Улучшение безопасности

Добавить:

Refresh tokens
JWT expiration
IP rate limit
10. Compiled Queries (ускорение EF Core)

EF Core может компилировать запросы.

Это ускоряет API на:

x2 — x10
11. Health Checks

Добавить endpoint проверки сервера.

/health

Показывает:

работает ли БД

работает ли API

работает ли кэш

12. Swagger улучшения

Добавить:

JWT авторизацию в Swagger

Чтобы можно было тестировать API прямо из Swagger.

13. Версионирование API

Сейчас уже есть:

/api/v1/

Позже можно сделать:

/api/v2/

Не ломая старые клиенты.
